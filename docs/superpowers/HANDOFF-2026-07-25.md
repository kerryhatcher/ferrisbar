## Things worth knowing before touching this code

- **`toml`'s `serde` feature is mandatory, not optional.** `toml::Table` and
  `toml::Value` are gated behind it in 1.1.3 — verified by removing it and
  getting 8 compile errors. The spec originally claimed parse-only would
  work; it does not. Config is still parsed by hand rather than via derive,
  because derive fails the whole document on one bad field.
- **`toml` is pinned `>=1.1, <1.2`** because 1.1.3 declares
  `rust-version = "1.85"` against our MSRV floor of 1.85.1 — a one-patch
  margin. An unbounded range lets `cargo update` break `just msrv` with no
  code change to blame.
- **The rotation ordering is load-bearing**: lock → stat → rotate → open →
  append, never open-then-lock. `Logger::append` opens by path on every
  write and the rotation check precedes that open, which satisfies it
  structurally. Do not give `append` a long-lived file handle.
- **Losing the lock race is a deferral, not a failure.** `acquire_lock`
  returning `None` propagates as `None` from `rotate_if_needed`, meaning
  "nothing to report". Turning that into an error string would emit a
  `log_rotate_failed` line on every render of every losing process.
- **`O_EXCL` exclusivity is mutation-covered by the unit test**
  `log::tests::a_held_lock_defers_rotation_without_losing_the_line`, which
  fails under a `create_new(true)` → `create(true)` mutation. The e2e
  concurrency test **cannot** detect that mutation and is not meant to — a
  losing writer produces a valid-but-misnumbered archive, and the real race
  window is microseconds against millisecond process spawn. Do not
  "strengthen" the e2e test to chase it; you will get flakiness, not
  coverage.
- **`tests/cli.rs` must never construct a bare `Command`.** Everything goes
  through `OVERRIDABLE_ENV_VARS` and `command_with_home`/
  `command_without_home`. Before that existed, the suite silently wrote a
  real `config.toml` and log into the developer's home directory and passed
  anyway — it did not fail, it leaked.
- **`#[allow(dead_code)]` count in `src/` is currently zero, deliberately.**
  Four separate tasks over-applied it (reviewers removed 7 of 10, 7 of 9,
  4 of 5, 5 of 10). The rule: rustc's dead-code analysis works from
  reachability roots, so an allow on a genuine root transitively covers
  everything it calls; annotations on downstream items suppress nothing —
  and clippy never flags a redundant allow, so useless ones live forever.
  If you find yourself adding one, the item probably wants a real caller.
